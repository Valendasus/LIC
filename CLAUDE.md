# LIC — как мы строим проект

LIC (Learn → Implement → Confirm) — личная платформа для обучения разработке. Пока для одного человека, но прогресс всегда хранится по пользователю: позже платформу можно открыть другим.

Связанные документы:
- **Дизайн — логика интерфейса, экраны, визуальный язык:** [docs/DESIGN.md](docs/DESIGN.md). Любой новый экран сначала сверяется с ним.
- **План и статус этапов:** [docs/PLAN.md](docs/PLAN.md). Подробно по Frontend — [docs/FRONTEND-PLAN.md](docs/FRONTEND-PLAN.md), по тренажёрам — [docs/TRAINERS.md](docs/TRAINERS.md), дерево тем — [docs/TOPIC-TREE.md](docs/TOPIC-TREE.md).
- **История изменений:** [CHANGELOG.md](CHANGELOG.md).
- **Запуск, форматы контента, команды:** [README.md](README.md).
- **Правила Next.js для агентов** (дописывает сам `next dev`): @AGENTS.md

## Главное: качество учебного материала

**Основа платформы — материал, по которому реально можно научиться самому и стать сильным специалистом.** Код, тренажёры и дизайн существуют ради него. При любом выборе — что делать первым, где потратить время, что считать готовым — побеждает качество материала.

Тема считается готовой, только когда выполнено всё:

1. **Полнота.** Тема покрывает всё, что нужно для работы и собеседований на её уровне (Junior, Middle, Senior): механизм, практическое применение, частые ошибки, граничные случаи, современные подходы. Пробел в важном — это не готовая тема.
2. **Глубина там, где она нужна.** Сложное объясняется подробно и по слоям: суть за минуту → как устроено внутри → как применять → где ломается. Простое — коротко. Объём определяется сложностью темы, а не шаблоном.
3. **Понятность.** Объяснение рассчитано на самостоятельное обучение, без преподавателя рядом:
   - каждое новое понятие вводится до того, как используется;
   - у каждого утверждения есть пример кода;
   - «почему так» объясняется, а не только «как».
4. **Точность и актуальность.** Только проверенное по первоисточникам (спецификации, официальная документация, release notes) и актуальное на дату проверки. Версии и дата проверки указываются в каждой теме.
5. **Много разной практики разного уровня.** У темы есть:
   - карточки на термины и определения;
   - вопросы на понимание: квиз, «что выведет», порядок;
   - задачи на код от разминки до тяжёлой или «босса», с лестницей подсказок и разбором;
   - где уместно — задачи на типы, React-задачи, демо.

   Задачи разные по типу (написать, починить, предсказать, сравнить, отрефакторить), а не вариации одной. Сложные задачи обязательно с подсказками.
6. **Связь с реальной работой.** Примеры из реального кода, вопросы, которые задают на собеседованиях, и «а если…» — как тема проявляется в проектах.
7. **Всё проверено автоматически.** Ответы «что выведет» запускаются, эталоны задач проходят тесты, заготовки — нет (`npm run content:check`, `npm test`, e2e).

**Перед тем как сказать «тема готова»,** пройтись по этим семи пунктам. Если хоть один не выполнен — тема не готова, а в отчёте честно сказано, чего не хватает.

## Стек

- **Приложение:** Next.js 16 (App Router, Turbopack), React 19, TypeScript 7. Tailwind 4, MDX.
- **Данные:** Prisma 7 и Postgres 17 в Docker (порт 5433). Рабочая база `lic`, тестовая — `lic_test`.
- **Повторение:** ts-fsrs 6 (FSRS-7).
- **Тренажёры:**
  - CodeMirror 6 — редактор кода;
  - Web Worker — запуск JavaScript;
  - TypeScript 6 (пакет `ts6`) — проверка типов и сборка React-задач, потому что у TypeScript 7 нет JS API;
  - iframe `/sandbox` с `@testing-library/dom` и user-event — React-задачи.
- **Тесты:** Vitest (jsdom) с порогом покрытия 100% и Playwright.

## Архитектура: Feature-Sliced Design

Код организован по [FSD](https://feature-sliced.design/). Слои сверху вниз; импортировать можно **только из слоёв ниже**:

| Слой | Где | Что лежит |
|---|---|---|
| **app** | `src/app/` | Маршруты Next.js, layout'ы, провайдеры, глобальные стили. Файлы маршрутов тонкие: получают данные и собирают страницу из `views` |
| **views** | `src/views/` | Страницы целиком: тема, ветка, сессия практики. Слой называется `views`, а не `pages`, чтобы не конфликтовать с Next.js |
| **widgets** | `src/widgets/` | Крупные самостоятельные блоки: сессия практики, панель практики, дерево ветки, шапка |
| **features** | `src/features/` | Действия пользователя, которые имеют ценность: оценить элемент, решить задачу, отметить освоение, перевернуть карточку |
| **entities** | `src/entities/` | Сущности предметной области: тема и дерево, элемент практики, прогресс, расписание повторения |
| **shared** | `src/shared/` | Без знаний о предметной области: UI-кит (`shared/ui`), утилиты (`shared/lib`), доступ к базе (`shared/api`), конфиг, токены дизайна |

- **Слайс** (папка внутри слоя) отдаёт наружу только свой `index.ts` — публичный API. Импорт из внутренних файлов чужого слайса запрещён.
- **Внутри слайса** — сегменты: `ui/` (компоненты), `model/` (состояние и логика), `api/` (серверные функции и запросы), `lib/` (вспомогательное), `config/`.
- **Слайсы одного слоя не импортируют друг друга.** Если двум фичам нужно общее — оно спускается в `entities` или `shared`.
- **Серверное и клиентское разделено.** Модуль с `node:fs` или базой не попадает в клиентский импорт: такие модули лежат в `api/` и отдают только серверные функции.
- **Публичный API слайса:** `index.ts` — безопасное для клиента (компоненты, типы, чистые функции, серверные действия); `server.ts` — модули с базой и файлами. Связь слайсов одного слоя — только через `@x/<потребитель>.ts`.
- **Правила проверяются тестом** `test/architecture.test.ts`: направление слоёв, публичный API, `@x`, клиент не импортирует серверное.

## Компоненты и переиспользование

1. **Сначала ищем в `shared/ui`, потом пишем.** Кнопка, поле, карточка, бейдж, панель, вкладки, модальное окно, подсказка, прогресс, пустое состояние, скелетон — по одному компоненту на всю платформу.
2. **Вариант, а не копия.** Новый вид кнопки — это новый `variant` или `size` у `Button`, а не новая кнопка со своими классами.
3. **Компоненты shared/ui:**
   - без бизнес-логики и знаний о темах и задачах;
   - доступны с клавиатуры, с видимым фокусом и ролями ARIA;
   - покрыты тестами.
4. **Логика отдельно от разметки.** Повторяющаяся логика — хук в `model/` или функция в `lib/`, а не копия в двух компонентах. Пример уже есть: один раннер и один экран задачи для кода, типов и React.
5. **Тренажёры собираются из общих частей:**
   - рамка задания (`Panel`);
   - итог проверки (`Outcome`);
   - блок кода (`CodeBlock`);
   - редактор (`CodeEditor`);
   - лестница подсказок;
   - кнопки оценки.

   Новый тренажёр переиспользует их.
6. **Цвета, отступы, радиусы и шрифты — только через токены.** Никаких `#hex` и произвольных `oklch(...)` в компонентах.

## Айдентика

### Палитра

Основная палитра платформы — монохромная фиолетово-серая, от тёмного к светлому. Закреплена 09.11.2026. **Только тёмная тема:** светлой нет.

| Токен палитры | HEX | Роль |
|---|---|---|
| `ink-900` | `#17151C` | фон страницы |
| `ink-800` | `#292531` | поверхность: карточки, панели |
| `ink-700` | `#45404F` | приподнятая поверхность, наведение, границы |
| `ink-500` | `#716879` | границы, разделители, неактивное |
| `ink-300` | `#AAA2B3` | вторичный текст, подписи |
| `ink-100` | `#E2DDE7` | основной текст, главная кнопка |
| `accent` | `#C7B8F0` | прогресс, активный шаг, ссылки, кольцо фокуса — утверждён 09.11.2026 |

**Контраст по WCAG 2.2 проверен для текста:**

| Пара | Контраст | Можно |
|---|---|---|
| `ink-100` на `ink-900` / `ink-800` / `ink-700` | 13,6 / 11,2 / 7,5 | любой текст |
| `ink-300` на `ink-900` / `ink-800` | 7,4 / 6,1 | любой текст |
| `ink-300` на `ink-700` | 4,1 | только крупный текст (от 18,66 px полужирный или 24 px обычный) |
| `ink-500` на `ink-900` | 3,4 | только границы, иконки, крупный текст — не для обычного текста |
| `ink-900` на `ink-100` | 13,6 | текст на главной кнопке |
| `accent` на `ink-900` / `ink-800` | 10,0 / 8,2 | любой текст |

**Статусные цвета** — токены `good` `#8FC4A2`, `warn` `#D9B46E`, `bad` `#E0959F`, `info` `#9DB2E0` (контраст в [docs/DESIGN.md](docs/DESIGN.md), раздел 5.1):
- приглушённые, в той же светлоте, что палитра, чтобы не выбиваться;
- контраст текста не ниже 4,5:1 на своих фонах;
- статус никогда не передаётся одним цветом — всегда ещё иконкой или словом.

**Токены** задаются в `src/app/globals.css` (Tailwind 4 `@theme`) в два слоя:
- палитра — `--color-ink-*`;
- смысловые токены — `--color-bg`, `--color-surface`, `--color-raised`, `--color-line`, `--color-text`, `--color-muted`, `--color-accent`, статусы.

Компоненты используют только смысловые токены. Тема одна, но смысловой слой оставляем: цвет меняется в одном месте, а не в каждом компоненте.

### Остальное в айдентике

- **Шрифты:** Inter для интерфейса, JetBrains Mono для кода. Шкала размеров — токенами, без случайных `text-[15px]`.
- **Радиусы и тени:** одна шкала на всю платформу. Скругления мягкие: палитра навеяна «таблетками».
- **Иконки:** один набор, одна толщина линии.
- **Голос:** по-русски, коротко, на «вы»; кнопки — глаголом («Проверить», «Дальше»); ошибки объясняют, что делать.
- **Никаких внутренних кодов и терминов в интерфейсе:** не «FE6», «item», «FSRS», «state», а «JavaScript», «задача», «повторение». Оценки — словами человека («Не вспомнил», «Вспомнил»), сроки — словами («вернётся через 2 дня»).

## UX/UI: уровень профессиональных платформ курсов

Ориентир — лучшие обучающие продукты: понятная навигация по курсу, ощущение прогресса, мгновенная обратная связь, ничего лишнего.

1. **Каждый экран отвечает на вопросы «где я», «что дальше» и «сколько осталось».** Хлебные крошки, прогресс ветки и темы, явная следующая кнопка, сессия с прогрессом.
2. **Все состояния спроектированы:**
   - загрузка (скелетоны, а не пустота);
   - пусто (что сделать, чтобы появилось);
   - ошибка (что случилось и как исправить);
   - успех.
3. **Мгновенная обратная связь:** результат проверки, сохранение, переход — с понятным откликом. Долгие операции показывают, что идёт работа.
4. **Клавиатура — полноценный способ работы:** горячие клавиши в тренажёрах, видимый фокус, никаких ловушек фокуса.
5. **Доступность — WCAG 2.2 AA.** Семантическая разметка, подписи, контраст, `prefers-reduced-motion`. Проверка axe в e2e.
6. **Движение со смыслом:** анимации 150–300 мс, подчёркивают изменение состояния (переворот, появление результата), не мешают и отключаются при `prefers-reduced-motion`.
7. **Адаптивность:** от 360 px, без горизонтальной прокрутки, удобные области касания (от 44 px), редактор и тренажёры работают на телефоне. Проверяется в e2e.
8. **Читаемость уроков:** колонка текста 60–75 знаков, ясная иерархия заголовков, код с подсветкой, примеры рядом с объяснением.
9. **Скорость:** без лишнего JavaScript на страницах. Тяжёлое (компилятор, редактор) загружается только там, где нужно. Целевые Core Web Vitals «хорошо».
10. **Мотивация без шума:** прогресс, регулярность за неделю, «на сегодня всё» — честно и спокойно. Без счётчика серии, таймеров и оценок времени.

## Правила работы

1. **Сначала тренажёры, потом наполнение.** Новая возможность платформы появляется раньше, чем контент под неё.
2. **Всё новое покрыто тестами:**
   - **e2e** (Playwright) на пользовательские сценарии;
   - **юнит- и интеграционные** тесты (Vitest) — покрытие 100% строк, ветвлений, функций и операторов. Порог зашит в `vitest.config.ts`.
   - Недостижимые ветки удаляются из кода, а не закрываются искусственными тестами.
3. **Перед тем как сказать «готово»,** выполнить и убедиться, что всё зелёное:
   - `npm run content:check`;
   - `npm run typecheck`;
   - `npm run test:coverage`;
   - `npm run test:e2e`.

   Каждая новая функция проверяется ещё и в режиме разработки. Новые экраны — на ширине телефона, планшета и десктопа.
4. **Журнал изменений.** После каждой законченной работы — запись в [CHANGELOG.md](CHANGELOG.md) и обновлённый статус в `docs/PLAN.md` и `docs/TRAINERS.md`.
5. **Коммиты** — после законченной и проверенной работы. Сообщение по-русски, кратко о сути.

## Правила контента

1. **Только актуальные источники:** официальная документация, release notes, спецификации. В каждом уроке `export const meta = { verified, versions }`: дата проверки и версии. `content:check` это требует.
2. **Все ответы проверяются кодом:**
   - вывод «что выведет» реально запускается;
   - эталон задачи проходит тесты, заготовка — нет;
   - React-эталоны прогоняются в `test/content/react-tasks.test.tsx` и в e2e.
3. **Без указания источника примеров.** Примеры из проектов пользователя используются как реальный код, но в контенте не пишется, из какого проекта или работы они взяты. Названия проектов допустимы только во внутренних документах `docs/`.
4. **Ключи элементов (`key`) не переименовываются** — к ним привязано расписание повторений.
5. **Задачи разного уровня:** warmup, easy, medium, hard, boss. Подсказки — лестницей (направление → приём → каркас → ключевая строка), к сложным обязательно. Разбор — почему так, альтернативы, что спросят на собеседовании.
6. **Язык интерфейса и контента** — русский, простой и ясный.
7. **Сначала исследование, потом урок.** Перед тем как писать или переписывать тему:
   - открыть её заметку в `docs/research/sources/<блок>/`. Если заметки нет — сначала собрать её по первоисточникам: что обязательно знать, тонкие места, что изменилось в последних версиях со статусом Baseline, источники с датой;
   - открыть вопросы листа в `docs/research/interview-questions.json` (порядок и правила — в `docs/research/interview-questions.md`). На каждый частый вопрос урок должен давать ответ, а карточки или задачи — его проверять;
   - каждое утверждение о поведении кода проверить запуском. Статус поддержки брать из web-features и MDN browser-compat-data, а не из статей;
   - учесть, что Node, в котором работает `content:check`, отстаёт от браузеров. Задачам на самые новые API (Temporal, `Iterator.concat`, `Math.sumPrecise`) нужен полифил в проверке или пометка.

## Окружение

- **Порты:**
  - dev — `localhost:3100` (`npx next dev -p 3100`);
  - e2e — 3300;
  - база — 5433.
- **Чужие серверы.** На `127.0.0.1:3100` и `127.0.0.1:3200` работают серверы другого проекта пользователя (портфолио). Их процессы не останавливать. Открывать LIC по адресу `localhost`, не `127.0.0.1`.
- **Тесты не трогают рабочую базу `lic`:** у них своя база `lic_test`.
- **Первая холодная сборка** с воркером компилятора идёт несколько минут, дальше работает кеш `.next/cache`.
