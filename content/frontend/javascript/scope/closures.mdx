## Learn

### Суть за минуту

Функция в JavaScript помнит место, где её **создали**, и продолжает видеть переменные оттуда, даже когда внешняя функция давно закончила работу. Эта связка «функция + окружение, где она родилась» и называется **замыканием**.

```js
function makeCounter() {
  let count = 0
  return () => ++count
}

const next = makeCounter()
next() // 1
next() // 2 — count живёт, хотя makeCounter уже вернула результат
```

### Как это устроено

Каждый вызов функции и каждый блок `{}` создают **лексическое окружение** — таблицу «имя → значение» со ссылкой на внешнее окружение. Когда код обращается к переменной, движок ищет её в текущей таблице, потом во внешней, и так до глобальной. Это и есть цепочка областей видимости.

Когда функция создаётся, она получает скрытую ссылку на окружение, в котором появилась (в спецификации — внутреннее поле `[[Environment]]`). Поэтому:

1. **Важно, где функция создана, а не где вызвана.** Это и значит «лексическая» область видимости.
2. **Замыкание хранит ссылку на переменную, а не копию значения.** Если переменная изменится, функция увидит новое значение.
3. **Каждый вызов внешней функции — новое окружение.** Два счётчика из `makeCounter()` независимы.

```js
const a = makeCounter()
const b = makeCounter()
a(); a()
b() // 1 — у b своё окружение и свой count
```

<Callout type="deep">
Окружение — это объект в куче. Пока на него ссылается хоть одна живая функция, сборщик мусора его не удалит. Современные движки, как правило, оставляют в нём только переменные, которые функции действительно используют, а остальные живут на стеке и исчезают после вызова. Поэтому замыкание не держит в памяти всю внешнюю функцию — но держит всё, что захватило, включая большие массивы.
</Callout>

### Классика: цикл и таймер

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i))
}
// 3, 3, 3

for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log(j))
}
// 0, 1, 2
```

`var` объявляет **одну** переменную на всю функцию: три колбэка замкнулись на одну и ту же `i`, а к моменту срабатывания таймеров она уже равна 3. `let` в заголовке цикла создаёт **новую привязку на каждую итерацию**: у каждого колбэка своя `j`.

До появления `let` эту проблему решали немедленно вызываемой функцией, которая создавала окружение на каждую итерацию. Такой код встречается в старых проектах:

```js
for (var i = 0; i < 3; i++) {
  ;(function (k) {
    setTimeout(() => console.log(k))
  })(i)
}
```

### Где замыкания работают на вас

**Приватное состояние.** До приватных полей классов (`#field`) это был единственный способ спрятать данные. Счётчик выше — пример.

**Фабрики функций.** Внешняя функция принимает настройки и возвращает готовую функцию.

<Example file="server/utils/validation.js" verdict="good">

```js
export const isInteger = (min, max) => (value) =>
  Number.isInteger(value) && value >= min && value <= max

const contractSchema = {
  durationMonths: isInteger(1, 120),
}
```

`isInteger(1, 120)` возвращает проверку, которая помнит границы. Схема читается как текст, а логика проверки написана один раз.

</Example>

**Состояние модуля.** Функции модуля замыкаются на переменные верхнего уровня этого модуля.

<Example file="frontend/app/core/api/client.ts" verdict="good">

Переменная `refreshChannel` объявлена на уровне модуля, а функция `getRefreshChannel()` создаёт `BroadcastChannel` один раз и дальше возвращает его же. Все вызовы внутри модуля видят одно и то же значение — это «ленивый синглтон» на замыкании. Снаружи модуля к переменной доступа нет.

</Example>

**Таймеры, обработчики, `debounce`, `memoize`, `once`** — всё это функции, которые хранят состояние между вызовами в замыкании. Вы реализуете их в задачах ниже.

### Замыкания в React: устаревшее значение

Каждый рендер компонента — новый вызов функции. Значит, у каждого рендера свои `props` и `state`, а обработчики и эффекты замыкаются на значения **своего** рендера.

```jsx
function Timer() {
  const [count, setCount] = useState(0)

  useEffect(() => {
    const id = setInterval(() => setCount(count + 1), 1000)
    return () => clearInterval(id)
  }, []) // эффект создан один раз, в первом рендере

  return <p>{count}</p>
}
```

Счётчик дойдёт до 1 и остановится: колбэк навсегда видит `count` из первого рендера, то есть 0. Это **устаревшее замыкание** (stale closure).

| Как исправить | Когда подходит |
|---|---|
| `setCount((c) => c + 1)` | Новое значение зависит только от предыдущего |
| Добавить `count` в зависимости | Эффект можно безболезненно перезапускать |
| `useEffectEvent` (React 19.2+) | Внутри эффекта нужно читать свежие значения, не перезапуская эффект |
| `useRef` с последним значением | Код вне эффектов или поддержка старых версий React |

<Callout type="mistake">
Отключать правило `react-hooks/exhaustive-deps`, чтобы «убрать предупреждение». Линтер указывает ровно на то место, где появится устаревшее замыкание. Лечится оно одним из способов из таблицы, а не комментарием.
</Callout>

### Частые ошибки

- **«Замыкание копирует значение».** Нет, оно держит ссылку на переменную. Отсюда и `3, 3, 3` в цикле с `var`.
- **«Замыкание — это вложенная функция».** Любая функция в JS замыкается на своё окружение, даже объявленная на верхнем уровне модуля.
- **Утечки памяти.** Забытый обработчик события или таймер удерживает всё, на что ссылается его замыкание. Поэтому эффекты в React должны снимать подписки в функции очистки.
- **Функции, созданные в цикле с `var`.** Используйте `let` или выносите тело в отдельную функцию.

<Task level="medium" title="Почини таймер в React">

Компонент должен каждую секунду увеличивать счётчик на значение `step` из пропсов. Сейчас счётчик застревает, а при смене `step` продолжает прибавлять старое значение.

```jsx
function Ticker({ step }) {
  const [total, setTotal] = useState(0)
  useEffect(() => {
    const id = setInterval(() => setTotal(total + step), 1000)
    return () => clearInterval(id)
  }, [])
  return <output>{total}</output>
}
```

<Hints hints={['Здесь два устаревших значения: total и step.', 'Для total подойдёт функциональное обновление.', 'Для step подумайте: нужно ли перезапускать интервал при его смене? Если нет — useEffectEvent.']}>

```jsx
function Ticker({ step }) {
  const [total, setTotal] = useState(0)
  const onTick = useEffectEvent(() => {
    setTotal((t) => t + step) // всегда свежий step
  })

  useEffect(() => {
    const id = setInterval(() => onTick(), 1000)
    return () => clearInterval(id)
  }, [])

  return <output>{total}</output>
}
```

`total` больше не читается из замыкания: React передаёт актуальное значение в функцию обновления. `useEffectEvent` возвращает функцию, которая всегда видит последние пропсы, и при этом не требует перезапуска эффекта. Более простой вариант без `useEffectEvent` — указать `[step]` в зависимостях: интервал будет перезапускаться при смене шага, что здесь тоже допустимо.

</Hints>
</Task>

<Question q="Что такое замыкание? Ответьте без фразы «функция помнит переменные».">
Функция вместе со ссылкой на лексическое окружение, в котором она была создана. При обращении к переменной поиск идёт по цепочке окружений начиная с этого, а не с того места, где функцию вызвали.
</Question>

<Question q="Почему цикл с var и setTimeout выводит 3, 3, 3, а с let — 0, 1, 2?">
`var` создаёт одну переменную на всю функцию, и все колбэки ссылаются на неё; к моменту срабатывания таймеров она равна 3. `let` в заголовке цикла создаёт новую привязку на каждую итерацию, поэтому у каждого колбэка своё значение.
</Question>

<Question q="Может ли замыкание привести к утечке памяти? Как?">
Да. Пока функция жива, живо и всё, что она захватила. Забытый обработчик события, таймер или подписка удерживают данные, даже если компонент или страница уже не используются. Защита — снимать подписки (функция очистки эффекта, `removeEventListener`, `clearInterval`, `AbortController`).
</Question>

<Question q="Что такое устаревшее замыкание в React и как его исправить?">
Обработчик или эффект видит значения того рендера, в котором создан. Если эффект создан один раз, он навсегда видит первое состояние. Исправления: функциональное обновление `setState(prev => …)`, правильные зависимости эффекта, `useEffectEvent` для чтения свежих значений без перезапуска, `useRef` для изменяемого значения.
</Question>

<Question q="Чем приватное поле класса #x отличается от приватности через замыкание?">
Оба недоступны снаружи. `#x` — синтаксис языка: поле принадлежит экземпляру, методы лежат в прототипе и общие для всех экземпляров. Через замыкание каждый экземпляр получает свои копии функций, что дороже по памяти при большом числе объектов, зато работает с любыми функциями, не только с классами.
</Question>

Типичная цепочка: «Что такое замыкание?» → «Что выведет цикл с var и setTimeout?» → «Как исправить без let?» → «Напишите debounce» → «Где в React бывают проблемы с замыканиями?». Сильный ответ показывает лексическое окружение, приводит пример из своего кода и упоминает утечки памяти.
