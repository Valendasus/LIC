## Learn

### Суть за минуту

К одному элементу почти всегда применяется несколько правил с одним и тем же свойством. **Каскад** — это алгоритм, который выбирает победителя. Он сравнивает объявления по шагам и останавливается на первом шаге, где есть разница. Специфичность — только один из этих шагов, и далеко не первый.

### Алгоритм каскада по шагам

1. **Источник и важность.** Чьё это объявление (браузера, пользователя, автора страницы) и есть ли `!important`.
2. **Контекст.** Для Shadow DOM: стили снаружи и внутри компонента.
3. **Стили в атрибуте `style`.** Они побеждают любые селекторы того же источника и важности.
4. **Слои `@layer`.**
5. **Специфичность селектора.**
6. **Порядок в коде.** При равенстве всего остального побеждает объявление, которое встретилось позже.

Порядок источников по силе, от сильного к слабому:

| Место | Что |
|---|---|
| 1 | Переходы (`transition`) |
| 2 | `!important` браузера |
| 3 | `!important` пользователя |
| 4 | `!important` автора |
| 5 | Анимации (`@keyframes`) |
| 6 | Обычные стили автора |
| 7 | Обычные стили пользователя |
| 8 | Обычные стили браузера |

Обратите внимание: `!important` **переворачивает** порядок источников. Так браузер и пользователь (например, с настройками доступности) могут гарантированно перебить стили сайта.

### Специфичность

Специфичность записывают тремя числами **(A, B, C)** и сравнивают слева направо, как версии программ:

| Компонент | Что считается |
|---|---|
| **A** | Селекторы по id: `#header` |
| **B** | Классы, атрибуты, псевдоклассы: `.btn`, `[type="email"]`, `:hover` |
| **C** | Теги и псевдоэлементы: `div`, `::before` |

Не считаются: `*`, комбинаторы (`>`, `+`, `~`, пробел).

| Селектор | Специфичность |
|---|---|
| `p` | (0, 0, 1) |
| `.card p` | (0, 1, 1) |
| `.card > .title:hover` | (0, 3, 0) |
| `#main .card` | (1, 1, 0) |
| `a[href^="https"]::after` | (0, 1, 2) |

Один id сильнее любого числа классов: (1, 0, 0) > (0, 99, 0). Числа не «переносятся».

**Особые псевдоклассы:**

- `:is()`, `:not()`, `:has()` берут специфичность **самого специфичного** аргумента: `:is(#a, .b)` весит как id.
- `:where()` весит **ноль**, каким бы ни было содержимое. Им удобно писать базовые стили, которые легко перебить.

```css
:where(.btn) { color: gray; }  /* (0, 0, 0) */
a { color: blue; }             /* (0, 0, 1) — побеждает */
```

### Слои: управлять порядком, а не воевать специфичностью

`@layer` задаёт порядок групп стилей. Слой, объявленный позже, сильнее — **независимо от специфичности** селекторов внутри.

```css
@layer reset, base, components, utilities;

@layer components {
  #app .card .title { color: black; }   /* (1, 2, 0), но слой слабее */
}
@layer utilities {
  .text-red { color: red; }             /* (0, 1, 0) — побеждает */
}
```

Правила слоёв, которые чаще всего забывают:

- **Стили вне слоёв сильнее любых слоёв** (для обычных объявлений).
- **С `!important` всё наоборот:** важное объявление в более раннем слое сильнее, а важное вне слоёв — слабее всех слоёв.

<Example file="globals.css (Tailwind 4)" verdict="good">

Tailwind 4 построен на нативных каскадных слоях: `theme`, `base`, `components`, `utilities`. Поэтому утилита вроде `text-red-500` перебивает стили компонентов не за счёт специфичности, а за счёт порядка слоёв. Свои стили, написанные вне слоёв, перебьют утилиты Tailwind. Это нужно помнить, когда «класс не применяется».

</Example>

<Example file="MUI и Emotion" verdict="review">

Стили MUI вставляются в `head` во время выполнения (Emotion). Порядок вставки определяет, кто сильнее при равной специфичности, и при подключении сторонних стилей это даёт неожиданные перебивания. Решения: настраивать точку вставки стилей или класть стили библиотеки в отдельный слой `@layer`.

</Example>

### Наследование

Если ни одно правило не задало свойство, некоторые свойства **наследуются** от родителя (в основном текстовые: `color`, `font-*`, `line-height`, `visibility`), а остальные получают начальное значение (`margin`, `border`, `background`).

Управлять этим можно ключевыми словами:

| Значение | Что делает |
|---|---|
| `inherit` | Взять у родителя |
| `initial` | Начальное значение из спецификации |
| `unset` | `inherit` для наследуемых свойств, `initial` для остальных |
| `revert` | Откатить к стилям браузера |
| `revert-layer` | Откатить к значению из предыдущего слоя |

<Callout type="mistake" title="Лечить конфликт через !important">
`!important` выигрывает сегодня и проигрывает завтра: следующий разработчик добавит свой `!important`, и начнётся гонка. Почти всегда правильнее понять, на каком шаге каскада проигрывает ваше правило, и исправить причину: порядок слоёв, лишний id в чужом селекторе, порядок подключения файлов.
</Callout>

### Как разбираться на практике

DevTools → Elements → Styles показывает все правила для элемента. Перечёркнутые — проиграли. Вкладка Computed для каждого свойства показывает, откуда взято итоговое значение. Наведите на селектор, и Chrome покажет его специфичность.

<Task level="easy" title="Какой цвет у ссылки?">

```html
<nav id="top"><a class="link" href="/">Главная</a></nav>
```

```css
#top a { color: green; }
.link { color: red !important; }
nav .link { color: blue; }
```

<Hints hints={['Проверьте шаги по порядку: сначала важность, потом специфичность.']}>

**Красный.** На шаге «источник и важность» объявление с `!important` сильнее обычных, до специфичности дело не доходит. Без `!important` победил бы зелёный: (1, 0, 1) больше, чем (0, 1, 1).

</Hints>
</Task>

<Task level="medium" title="Слои и стили вне слоёв">

```css
@layer base, components;

@layer components {
  .btn { background: blue; }
}
@layer base {
  #app .btn { background: gray; }
}
.btn { background: green; }
```

Какой фон у `.btn` внутри `#app`? А если дописать `!important` к правилу в слое `base`?

<Hints hints={['Слои сравниваются раньше специфичности.', 'Обычные стили вне слоёв сильнее всех слоёв.', 'С !important порядок слоёв переворачивается, а стили вне слоёв становятся самыми слабыми.']}>

1. **Зелёный.** Обычное объявление вне слоёв сильнее любых слоёв, специфичность не важна.
2. **Серый.** Среди важных объявлений более ранний слой (`base`) сильнее, а важные объявления вне слоёв самые слабые. Других важных объявлений здесь нет, поэтому побеждает `base`.

</Hints>
</Task>

<Task level="hard" title="Выбраться из войны !important">

В проекте 40 правил с `!important`: так перебивали стили UI-библиотеки и друг друга. Нужно избавиться от них, не изменив внешний вид. Опишите план и покажите, как будет выглядеть подключение стилей.

<Hints hints={['Первым делом нужен способ быстро заметить, что внешний вид изменился.', 'Решите, кто кого должен перебивать: сброс, библиотека, ваши компоненты, утилиты.', 'Порядок групп можно задать слоями, а стили библиотеки положить в слой при импорте.', 'Убирайте !important по одному и проверяйте вид после каждого шага.']}>

1. **Страховка:** скриншот-тесты ключевых страниц (Playwright `toHaveScreenshot`) до начала работ.
2. **Порядок групп:** `@layer reset, vendor, base, components, utilities;` в самом начале главного файла стилей.
3. **Библиотека в слой:** `@import url('library.css') layer(vendor);` — теперь любые ваши стили в более поздних слоях сильнее её независимо от специфичности.
4. **Свои стили** разложить по слоям `base`, `components`, `utilities`.
5. **Убирать `!important` по одному,** прогоняя скриншот-тесты. Оставить только там, где он осмыслен: например, утилиты-исключения вроде `.visually-hidden`.
6. **Правило в линтере** (Stylelint `declaration-no-important`), чтобы новые не появлялись.

**Разбор:** проблема была не в специфичности, а в отсутствии договорённости о порядке. Слои превращают её в явное правило.

</Hints>
</Task>

## Confirm

<Question q="Назовите шаги каскада по порядку.">
Источник и важность → контекст (Shadow DOM) → стили в атрибуте `style` → слои `@layer` → специфичность → порядок в коде.
</Question>

<Question q="Как считается специфичность и почему 11 классов не перебивают один id?">
Три числа (id; классы, атрибуты и псевдоклассы; теги и псевдоэлементы) сравниваются слева направо. Разряды не переносятся: (1, 0, 0) больше (0, 11, 0), потому что сравнение заканчивается на первом числе.
</Question>

<Question q="Чем :is() отличается от :where()?">
Оба принимают список селекторов. `:is()` получает специфичность самого специфичного аргумента, `:where()` всегда весит ноль. `:where()` удобен для базовых стилей, которые должно быть легко перебить.
</Question>

<Question q="Кто сильнее: обычный стиль вне слоёв или обычный стиль в слое? А с !important?">
Без `!important` сильнее стиль вне слоёв. С `!important` наоборот: важные объявления в слоях сильнее важных вне слоёв, а среди слоёв сильнее более ранний.
</Question>

<Question q="Какие свойства наследуются и как это изменить?">
В основном текстовые: `color`, `font-*`, `line-height`, `visibility`, `cursor`. Остальные (`margin`, `padding`, `border`, `background`) не наследуются. Управлять можно значениями `inherit`, `initial`, `unset`, `revert`, `revert-layer`.
</Question>

<Callout type="interview">
Частый вопрос: «Почему мой стиль не применяется?». Сильный ответ — не «добавлю !important», а последовательность: открыть DevTools, найти перечёркнутое правило, понять, на каком шаге каскада оно проиграло, и исправить причину. Упомяните `@layer` — его знают далеко не все кандидаты.
</Callout>
