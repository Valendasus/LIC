## 09.11.2026 — практика в режиме фокуса, рабочее пространство задачи, итог сессии

- **Сессия на весь экран без навигации.** Сверху: выход (Esc), название сессии, результаты отрезками (вспомнил, с трудом, не вспомнил, текущий, впереди), счётчик. Esc не срабатывает в редакторе кода и пока сохраняются ответы. Служебная строка «Элементов в ветке… в изучении…» убрана.
- **Карточка:** вопрос и ответ на одной карточке через разделитель. Оценки словами — «Не вспомнил», «С трудом», «Вспомнил», «Легко». Срок словами — «вернётся через 2 дня». Клавиша — отдельной меткой в углу.
- **Сроки повторения словами везде:** «через минуту», «завтра», «через 3 дня», «через 2 недели», «через месяц».
- **Задача — рабочее пространство на две колонки.** Слева условие, лестница подсказок с индикатором и честной фразой об оценке, после решения — итог и разбор. Справа редактор, результаты (упавшие тесты раскрыты, пройденные свёрнуты), предпросмотр. Внизу действия.
- **«Сдаться и посмотреть решение»** сначала переспрашивает. **«Дальше»** — только после решения, со сроком возвращения. Пока код отличается от заготовки, видно «Черновик сохранён».
- **Итог сессии:** число ответов, доля «вспомнил» с полосой результатов, что вернётся (сегодня, завтра, на неделе, позже), тема с наибольшим числом ошибок, «Вернуться к теме» и «На „Сегодня“».
- **«На сегодня всё»** и «В ветке пока нет практики» — по центру, с выходом и свободной тренировкой.

**Проверено:** 290 юнит-тестов, покрытие 100%; 41 e2e-сценарий.

## 09.11.2026 — тема по шагам Learn · Implement · Confirm

- **Тема — три шага-вкладки** (`shared/ui/StepTabs`, шаблон Tabs из WAI-ARIA APG): кружок со статусом, «Learn · понять», статус словами, полоска шага. Выбранный шаг — в адресе (`#implement`). Стрелки, Home и End переключают шаги. Внизу шага — «Дальше: …», на последнем — «Следующая тема».
- **Урок раскладывается по шагам автоматически:** содержимое MDX делится по заголовкам `## Learn / Implement / Confirm / Источники`. Заголовки третьего уровня получают id и становятся оглавлением шага (справа, от 1536 px).
- **Learn:** объяснение, источники, дата проверки.
- **Implement:** задачи темы со статусом «решена», типом и сложностью; кнопки «Решать задачи» и «Вопросы на понимание»; задачи с разбором из урока.
- **Confirm:** карточки темы, свободная тренировка, вопросы из урока, самооценка освоения.
- **Слева — темы модуля** со статусами: освоена, в процессе, не начата, готовится (от 1280 px).
- **Тема без урока** честно говорит «Урок по этой теме готовится», практика при этом доступна. Цели темы свёрнуты в одну строку. На телефоне шаги компактные, в одну строку.
- **В Vitest MDX собирается** с тем же провайдером компонентов, что и в Next.js.

**Проверено:** 284 юнит-теста, покрытие 100%; 41 e2e-сценарий.

## 09.11.2026 — экран «Сегодня»

- **Главная — «Сегодня»:** приветствие по времени суток и дата. Карточка повторения: сколько элементов, сколько повторений и новых, состав (карточки, вопросы, задачи), одна кнопка «Начать повторение».
- **Состояния карточки повторения:** первый вход («Начните с первой темы»), есть что повторить, «На сегодня всё» со свободной тренировкой.

- **«Продолжить»** — последняя тема с метками шагов Learn / Implement / Confirm. **«Дальше по пути»** — следующие темы в порядке курса. Внизу — специальности.
- **Данные** (`entities/review/api/today.ts`): активность за неделю, шаги темы, последняя тема, следующие темы. В счётчиках появился состав сессии.
- **Общие части:** метки шагов `TopicStepChips` (понадобятся на странице темы), склонение по числу `plural`/`count` в `shared/lib`.

## 09.11.2026 — переход на Feature-Sliced Design

- **Код разложен по слоям:** `shared`, `entities` (тема, прогресс, пользователь, элемент практики, расписание, очередь повторения, урок), `features` (отметить освоение, ответить, оценить, решить задачу), `widgets` (каркас, сессия, панель практики), `views` (страницы). Маршруты в `app/` только переэкспортируют страницы.
- **Публичный API у каждого слайса:** `index.ts` для всего и `server.ts` для кода с базой и файлами; перекрёстные связи сущностей — через `@x`.
- **Новый архитектурный тест** `test/architecture.test.ts` проверяет правила FSD на каждом запуске.
- **Поведение не менялось.**

**Проверено:** 224 юнит-теста, покрытие 100%; 34 e2e-сценария.

## 09.11.2026 — задачи на типы и React-задачи (этап 4 тренажёров)

**Новое:**
- **Задачи на типы (T6).**
  - Проверяет компилятор TypeScript 6 в Web Worker. Воркер живёт между запусками: первая проверка около секунды, следующие — десятки миллисекунд.
  - Результат по каждому тесту `Expect<…>` или `// @ts-expect-error`. Ошибки в решении — отдельным пунктом с номером строки.
  - 8 задач:
    - утилитарные типы — `Pick`, `Omit`, `DeepReadonly`;
    - уровень типов — кортеж в объединение, `Awaited`, `Trim`, пути и значения по пути;
    - обобщения — `groupBy`.
- **React-задачи с предпросмотром (T7).**
  - Сборка — TypeScript 6 с защитой от бесконечных циклов.
  - Тесты — в iframe-песочнице `/sandbox` с Testing Library и user-event.
  - После тестов показывается живой компонент.
  - 5 задач: счётчик, список дел с фильтром, форма регистрации, `useDebouncedValue`, доступные вкладки по WAI-ARIA.
- **Проверки элементов в тестах задач:** `toBeInTheDocument`, `toHaveTextContent`, `toHaveValue`, `toHaveAttribute`, `toBeDisabled`, `toBeChecked`, `toHaveFocus`.
- **Страницы сайта перенесены в группу маршрутов `(site)`,** чтобы у песочницы не было шапки. Адреса не изменились.
- **Правила проекта** — `CLAUDE.md`, этот журнал, обновлённый `docs/PLAN.md` со статусом этапов.

**Исправлено:**
- **Ошибка рендера в песочнице терялась.** В продакшен-React она уходила в `onUncaughtError`, и тест видел только «элемент не найден». Теперь `render` бросает настоящую причину.
- **В режиме разработки тесты React-задачи запускались дважды** (StrictMode) и монтировали предпросмотр повторно.
- **Testing Library для React не работает с продакшен-React** — там нет `act`. Поэтому `render` и `renderHook` для песочницы свои, на `flushSync`.
- **Регулярное выражение в тексте ошибки выводилось как `{}`.**

**Проверено:**
- 221 юнит-тест, покрытие 100%;
- 34 e2e-сценария;
- эталоны всех задач на типы и React-задач решаются в настоящем браузере.

## 09.11.2026 — задачи на код (этап 3) и логика карточек

**Новое:**
- **Задачи на код (T5).**
  - Редактор CodeMirror 6, тесты в Web Worker; бесконечный цикл останавливается через 5 секунд.
  - Лестница подсказок, черновик в браузере.
  - Эталон не уходит в браузер до решения.
  - Оценка ставится сама: открыто решение → «Снова», с подсказками или не с первого запуска → «Трудно», иначе → «Хорошо».
- **11 задач:**
  - замыкания — счётчик, `once`, `memoize` с LRU, `debounce`;
  - асинхронность — `delay`, таймаут, свой `Promise.all`, параллельность с лимитом, обработка без заморозки страницы;
  - специфичность — сравнение и подсчёт по селектору.
- **`content:check`** проверяет, что эталон проходит все тесты, а заготовка проваливает хотя бы один.

**Исправлено в логике карточек:**
- прямая и обратная карточка одного термина больше не попадают в одну сессию;
- карточка после «Снова» не пропадает до завтра, если зайти раньше срока: её берут заранее;
- число на кнопке «Учить и повторять» совпадает с длиной сессии;
- двойной клик или зажатая клавиша больше не засчитывают оценку дважды.

**Проверено:**
- 160 юнит-тестов, покрытие 100%;
