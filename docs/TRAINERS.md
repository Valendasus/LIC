# LIC · Тренажёры

> Как устроены тренажёры платформы: общая модель, виды, форматы контента, проверка, связь с повторением.
> Сначала проектируем все, потом строим по очереди и наполняем.
> Составлено 08.11.2026.

## 1. Общая модель

### 1.1. Элемент практики

Любое упражнение на платформе — **элемент практики** (item). У каждого элемента:

| Поле | Значение |
|---|---|
| `id` | `<id темы>#<ключ>`, например `frontend/javascript/scope/closures#closure-def`. Стабилен: прогресс привязан к нему, поэтому ключи не переименовываются |
| `kind` | Вид тренажёра: `card`, `quiz`, `output`, `order`, `code` и т. д. |
| Тема | Лист дерева, к которому относится элемент |
| Содержание | Зависит от вида |

Элементы лежат в репозитории рядом с темой:
- `<тема>.mdx` — объяснение;
- `<тема>.cards.yaml` — карточки;
- `<тема>.practice.yaml` — остальные элементы (квизы, «что выведет», задачи).

### 1.2. Повторение по FSRS

Все элементы, которые проверяют **вспоминание**, попадают в общую систему интервального повторения:
- **Алгоритм:** FSRS-7 из библиотеки `ts-fsrs` 6.
- **Цель:** 90 % вспоминания при минимуме повторений.
- **Хранение:** состояние элемента для пользователя — в таблице `review_items`, каждый ответ — в `review_logs`. По журналу позже можно подобрать персональные параметры FSRS.

Оценка бывает двух видов:

| Тип тренажёра | Кто ставит оценку |
|---|---|
| **Самооценка** (карточки, вопросы с открытым ответом) | Пользователь: «Снова», «Трудно», «Хорошо», «Легко» |
| **Автопроверка** (квиз, «что выведет», задачи с тестами) | Платформа выводит оценку из результата |

Правило автооценки:

| Результат | Оценка FSRS |
|---|---|
| Неверно или открыто решение | Снова |
| Верно, но с 2+ подсказками или со второй попытки | Трудно |
| Верно с 0–1 подсказкой | Хорошо |
| Верно без подсказок и быстрее медианного времени | Легко |

### 1.3. Режимы занятий

| Режим | Что попадает | Влияет на расписание |
|---|---|---|
| **Повторение** (ежедневное) | Все элементы, срок которых наступил, плюс до N новых в день. Темы перемешаны: чередование помогает запоминать | Да |
| **Изучение темы или блока** | Элементы выбранной ветки дерева: сначала новые, потом подошедшие | Да |
| **Свободная тренировка** | Все элементы ветки в случайном порядке, например перед собеседованием | Нет |
| **Только трудные** | Элементы с наибольшим числом ошибок | Нет |

Лимит новых элементов в день по умолчанию 20 и настраивается: темп выбираете вы.

### 1.4. Связь с уровнем освоения темы

Отметки «знаю / понимаю / применяю / владею» сейчас ставятся вручную. Позже платформа будет подсказывать уровень по данным практики:
- **«Понимаю»** — все карточки темы выучены (вышли из стадии изучения);
- **«Применяю»** — решены задачи уровня «средняя» без решения;
- **«Владею»** — решена тяжёлая задача или проект.

Окончательное решение остаётся за вами.

## 2. Виды тренажёров

### T1. Карточки ⭐ строим первым

**Зачем:** термины, определения, короткие ответы, синтаксис. Самое частое и быстрое повторение.

**Как выглядит:**
1. Вопрос на лицевой стороне. Ответить мысленно или вслух.
2. Клик, пробел или Enter — карточка переворачивается.
3. Оценить себя: «Снова», «Трудно», «Хорошо», «Легко». На каждой кнопке видно, когда карточка вернётся. Клавиши 1–4.
4. «Снова» возвращает карточку в эту же сессию через несколько минут.

**Типы карточек:**

| Тип | Лицо | Оборот | Пример |
|---|---|---|---|
| `term` | Термин | Определение | «Замыкание» → «функция + ссылка на лексическое окружение…» |
| `term` + `reverse: true` | Плюс обратная карточка: определение → термин | | Проверяет и узнавание, и вспоминание |
| `qa` | Короткий вопрос | Короткий ответ | «Какой уровень специфичности у :where()?» → «Нулевой» |
| `code` | Фрагмент кода и вопрос | Ответ и объяснение | «Что выведет…?» |
| `cloze` (позже) | Текст с пропуском | Пропущенное слово | «Задача длиннее ___ мс считается длинной» |

**Формат** (`<тема>.cards.yaml`):

```yaml
- key: closure-def          # стабильный ключ, не переименовывать
  type: term
  front: Замыкание
  back: Функция вместе со ссылкой на лексическое окружение, в котором она была создана.
  example: |                # необязательно: показывается на обороте
    ```js
    const add = (a) => (b) => a + b
    ```
  reverse: true             # создать обратную карточку
```

В текстах карточек работает упрощённая разметка: `код`, **жирный**, блоки кода, списки.

**Правила хороших карточек:**
- **Один факт.** Карточка проверяет одно, а не перечень из пяти пунктов.
- **Однозначный ответ.** Ответ можно вспомнить и честно сверить.
- **Своими словами.** Не цитата из документации, которую можно только «узнать».
- **Свой ключ на каждый факт.** Если кажется, что нужна большая карточка, лучше разбить её на несколько.

### T2. Квиз (выбор ответа)

**Зачем:** различать похожие понятия, ловить типичные заблуждения. Слабее карточек для запоминания: узнать проще, чем вспомнить. Поэтому квизы используются для проверки понимания, а не как основа повторения.

**Как выглядит:**
- Вопрос, иногда с кодом. Варианты перемешиваются.
- После выбора — сразу «верно» или «неверно» и **объяснение каждого неверного варианта**: почему он кажется правильным.
- Типы: один ответ, несколько ответов, «верно или неверно».

```yaml
- key: layer-vs-unlayered
  kind: quiz
  question: Кто сильнее — обычное правило вне слоёв или в слое @layer?
  options:
    - text: Правило вне слоёв
      correct: true
    - text: Правило в слое, если у него выше специфичность
      why: Слои сравниваются раньше специфичности.
  explain: Обычные объявления вне слоёв сильнее любых слоёв.
```

### T3. «Что выведет»

**Зачем:** event loop, приведение типов, `this`, замыкания, рендеры React.

**Как выглядит:** код → свой ответ построчно → проверка → объяснение по шагам.

**Проверка:** код реально выполняется в изолированном воркере и сравнивается с ответом. Ответ, записанный в контенте, тоже проверяется при сборке: если он разошёлся с реальным выводом, сборка падает.

```yaml
- key: microtask-order
  kind: output
  code: |
    setTimeout(() => console.log('A'))
    Promise.resolve().then(() => console.log('B'))
    console.log('C')
  explain: Синхронный код → все микрозадачи → задача.
```

### T4. Порядок

**Зачем:** последовательности — порядок вывода, шаги каскада, фазы рендера, этапы деплоя.

**Как выглядит:** перетащить или нажимать элементы в нужном порядке. Ошибочные позиции подсвечиваются.

### T5. Задачи на код с тестами

**Зачем:** главный тренажёр «Implement» для JS и TS.

**Как выглядит:**
- **Редактор:** CodeMirror 6 с подсветкой, автоотступами и сохранением черновика.
- **Запуск:** «Запустить» (Ctrl/⌘+Enter) выполняет тесты в Web Worker с ограничением по времени. Показывается, какие тесты прошли, что ожидалось и что получено, плюс `console.log`.
- **Подсказки:** лестница из раздела 3 — направление → приём → каркас → ключевая строка → решение с разбором.
- **После решения:** вариация задачи и «а если…».

**Проверка контента:** эталонное решение обязано пройти все тесты, а заготовка — провалить хотя бы один. Это проверяется автоматически тем же модулем, что запускает тесты в браузере.

**Что сделано (этап 3):**
- **Редактор:** CodeMirror 6 — подсветка, автоскобки, история, Tab для отступа, Ctrl/⌘+Enter для запуска.
- **Черновик:** хранится в браузере.
- **Запуск:** новый Web Worker на каждый запуск, остановка через 5 с. Отдельный тест ждёт до 2 с.
- **Результат:** видно, какие тесты прошли и какие нет, и почему (ожидалось / получено), плюс вывод `console.log`.
- **Эталон:** не уходит в браузер вместе с сессией. Его выдаёт серверная функция `revealSolution`, когда тесты пройдены или нажато «Показать решение».
- **Автооценка** по правилу раздела 1.2. «Легко» пока не ставится: для него нужно медианное время решения, а данных о нём ещё нет.
- **Пока нет:** вариации задачи после решения и «а если…». Последнее сейчас живёт в разборе.

### T6. Задачи на типы

**Зачем:** TypeScript на уровне типов.

**Проверка:** компилятор TypeScript в браузере. Решение проходит, если в файле нет ошибок типов, в том числе в проверках `Expect<Equal<A, B>>`. Используется JS-компилятор TypeScript 6 (пакет `ts6`), потому что у TypeScript 7 нет JavaScript API.

**Что сделано:**
- **Воркер компилятора** живёт между запусками. Первая проверка около секунды: загрузка компилятора и разбор стандартной библиотеки. Дальше — десятки миллисекунд.
- **Стандартная библиотека** (`lib.es2023` + `lib.dom`) отдаётся статическим JSON `/ts-lib`.
- **Результат по каждому тесту:** строка `Expect<…>` или `@ts-expect-error`. Ошибки в решении — отдельным пунктом с номером строки.

### T7. React-задачи с предпросмотром

**Зачем:** UI-задачи как на «machine coding»-собеседовании.

**Как выглядит:**
- **Предпросмотр:** код компонента собирается в браузере и показывается после тестов. Сборщик — TypeScript 6 из T6, а не esbuild-wasm: компилятор уже загружен, и в нём есть трансформации для защиты циклов.
- **Тесты:** Testing Library (`@testing-library/dom`) и user-event в iframe-песочнице. `render` и `renderHook` свои, без `act`: в продакшен-сборке React его нет.
- **Защита:**
  - бесконечный цикл останавливает счётчик, вставленный в каждый цикл при сборке;
  - ошибка рендера показывается как настоящая причина;
  - на каждый запуск — новый iframe.
- **Доступность:** сценарии с клавиатуры есть в тестах задач (вкладки, форма). Проверка axe — **пока нет**.

### T8. CSS-задачи

**Зачем:** вёрстка без «на глаз».

**Проверка:**
- Результат сравнивается с эталоном попиксельно на нескольких ширинах. Видно процент совпадения и маску различий.
- Дополнительные правила задачи, например «без медиазапросов» или «без `position: absolute`».

### T9. Найди баг

**Зачем:** код-ревью и внимательность.

**Как выглядит:** фрагмент кода, часто из реальных проектов. Нужно кликнуть по строке с проблемой и выбрать тип проблемы. Затем — разбор и исправленный вариант.

### T10. Отладка по симптомам

**Как выглядит:** мини-приложение работает неправильно, есть описание симптома. Нужно найти причину и исправить; исправление подтверждает тест.

### T11. Производительность и доступность

**Как выглядит:** задачи с измеримой целью:
- «рендер списка меньше 16 мс»;
- «ни одной задачи длиннее 50 мс»;
- «axe без нарушений, всё доступно с клавиатуры».

### T12. Проектные задания

**Где:** в вашем собственном репозитории.

**Проверка:** чек-лист приёмки и тесты Playwright, которые даёт платформа.

### T13. System design

**Как выглядит:** условие → свой разбор по шаблону RADIO с таймером → эталонный разбор → самопроверка по списку критериев.

### T14. Пробное собеседование

**Как выглядит:**
- **Блиц:** вопросы из выбранных веток на время, ответ вслух, затем эталон и самооценка.
- **Отчёт:** в конце — список слабых тем.

### T15. Интерактивные демо

**Зачем:** часть «Learn», не проверка.

**Как выглядит:** пошаговые визуализации — event loop, каскад, рендер React, кеш Next.js, виртуализация.

## 3. Лестница подсказок (для T5–T11)

1. **Направление:** что заметить в условии.
2. **Приём:** какой инструмент подходит.
3. **Каркас:** структура решения без логики.
4. **Ключевая строка:** самое неочевидное место.
5. **Решение с разбором:** почему так, сложность, альтернативы, как спросят на собесе.

Число открытых подсказок влияет на автооценку FSRS (раздел 1.2).

## 4. Порядок разработки

| Этап | Что строим | Зачем первым |
|---|---|---|
| **1** ✅ | Повторение по FSRS, **T1 карточки**, режимы из раздела 1.3, счётчик «к повторению» | Основа запоминания, нужна для всех тем |
| **2** ✅ | T2 квиз, T3 «что выведет», T4 порядок (перенос готовых вопросов и задач — при наполнении тем) | Быстрые проверки понимания, контент частично готов |

| **6** | T12 проекты, T13 system design, T14 собеседование | Финальная подготовка |

## 5. Хранение

| Таблица | Что |
|---|---|
| `review_items` | Состояние элемента для пользователя: поля FSRS (стабильность, сложность, срок, стадия, число повторений и ошибок) |
| `review_logs` | Каждый ответ: оценка, время ответа, состояние до ответа. Нужно для статистики и подбора параметров FSRS |
| `task_attempts` (этап 3) | Попытки решения задач: код, результат тестов, подсказки |

Контент в базе не хранится, только ссылки на элементы по `id`. Поэтому правка текста карточки не сбрасывает её расписание. Если смысл карточки изменился, ей дают новый ключ.
