# LIC — платформа для обучения разработке

> **LIC = Learn → Implement → Confirm.** Три шага, из которых состоит каждая тема:
> **Learn** — понять (объяснение, примеры, разбор реального кода);
> **Implement** — сделать руками (задачи, тренажёры, проекты);
> **Confirm** — подтвердить, что знание держится (вопросы, повторение по FSRS, пробные собеседования).
> Документ — общий план. Составлен 08.11.2026, обновлён 09.11.2026.
> Что уже сделано — раздел 7 и [CHANGELOG.md](../CHANGELOG.md). Как ведём работу — [CLAUDE.md](../CLAUDE.md).

## 1. Зачем платформа

Цель одна: **освоить профессию до уровня, на котором берут на работу, и не терять знания потом.** Отсюда три требования:

1. **Полнота.** В дереве должны быть все темы, которые реально нужны для работы и собеседований по специальности, а не случайный набор статей.
2. **Практика на реальном коде.** У каждой темы есть раздел «Пример из проекта»: как тема реализована в smallCRM, avt-team, портфолио или лендинге, с путями к файлам и честной оценкой (хорошее решение или спорное). Неважно, кто писал код: это живая база примеров. Каталог — [PROJECTS-KB.md](PROJECTS-KB.md).
3. **Запоминание.** Темы не просто читаются: по ним есть вопросы, задачи с автопроверкой и плановое повторение.

**Аудитория.** Сейчас — только вы. Позже, возможно, другие люди, поэтому прогресс сразу хранится с привязкой к пользователю, а контент отделён от прогресса. Вход и роли добавляются без переделки.

Платформа не привязана к одной вакансии. Подготовка к конкретной вакансии — один из будущих «режимов собеседования» внутри неё.

## 3. Логика дерева

### 3.1. Уровни

```
Специальность        Frontend, Backend, Fullstack, DevOps …
└─ Блок              «JavaScript», «Базы данных», «Безопасность»
   └─ Тема           «Асинхронность»
      └─ Подтема     «Event loop»
         └─ …        глубина не ограничена, но обычно 3–5 уровней
            └─ Лист  единица обучения: объяснение, вопросы, задачи
```

### 3.2. Главное решение: дерево для навигации, граф для зависимостей

- **Одна тема хранится один раз,** а специальности на неё ссылаются. «HTTP», «Git» или «Безопасность» нужны и фронтенду, и бэкенду; при копировании прогресс и правки расходились бы.
  - **Fullstack** собирается из блоков Frontend, Backend и DevOps плюс свои «сквозные» темы.
- **Пререквизиты — отдельные связи.** «React → Хуки» требует «JS → Замыкания». Платформа подскажет, что пройти раньше, и не даст повторять верх без низа.

### 3.3. Что есть у каждого узла

| Поле | Зачем |
|---|---|
| Уровень | Junior, Middle или Senior: что нужно для первой работы, а что потом |
| Цели | 2–5 проверяемых умений по Блуму: «объяснить, почему…», «написать…», «найти ошибку в…» |
| Объяснение | Своими словами, с примерами и схемами. Источник — первичная документация (MDN, react.dev, nodejs.org, postgresql.org, OWASP) |
| Частые ошибки | Что путают и где ошибаются на практике |
| Пример из проекта | Где и как это реализовано в реальном коде, пути к файлам, оценка: хорошее решение или спорное |
| Вопросы | Для повторения, с открытым ответом: вспоминать, а не выбирать |
| Задачи | С автопроверкой (JS, TS, SQL) или с чек-листом приёмки (проектные) |
| Вопросы собеса | Как формулируют на интервью и что ждут в ответе |
| Источники | Ссылки на документацию и сильные статьи |

### 3.4. Прогресс по узлу

| Уровень | Что значит |
|---|---|
| 0. Не начато | — |
| 1. Знаю | Прочитал и узнаю |
| 2. Понимаю | Объясняю своими словами |
| 3. Применяю | Решаю задачи без подсказок |
| 4. Владею | Применил сам, объясняю компромиссы, разбираю реальный пример |

- Прогресс родителя складывается из детей.
- Повторения по FSRS со временем снижают оценку, если вопрос забыт.

## 5. Как будет работать обучение

1. **Изучение:** объяснение, затем сразу 2–3 вопроса «своими словами» и одна задача.
2. **Повторение:** каждый день очередь по FSRS. Темы перемешаны, а не идут подряд.
3. **Практика:** задачи с автопроверкой — JavaScript в Web Worker, типы TypeScript компилятором в браузере, React-компоненты в песочнице с Testing Library (всё это уже работает), позже SQL в браузерном Postgres через [PGlite](https://pglite.dev/). Проектные задачи проверяются по чек-листу и на реальных проектах.
4. **Собеседование:**
   - блиц по выбранным веткам;
   - пробное интервью по вашему проекту: «расскажи про мультитенантность smallCRM»;
   - разбор тестовых заданий.
5. **Проекты:** для каждого проекта есть карта тем, на которых он держится, разбор сильных и спорных решений и рассказ о проекте за 2 и за 10 минут.

## 6. Технологии самой платформы

Сама платформа — ещё один проект для портфолио и практика на нужном стеке.

| Часть | Выбор | Почему |
|---|---|---|
| Приложение | Next.js 16 (App Router), React 19, TypeScript | Ваш основной стек и самый частый запрос на рынке |
| Контент | Файлы MDX и YAML в репозитории | Правится как код, версии в git, легко дополнять |
| Прогресс | Postgres в Docker + Prisma | Prisma и Postgres уже знакомы по smallCRM и востребованы |
| Повторение | [ts-fsrs](https://github.com/open-spaced-repetition/ts-fsrs) | Открытая реализация FSRS |
| Редактор кода | CodeMirror 6 | Уже используется в smallCRM |
| Проверка типов и сборка React-задач | TypeScript 6 в Web Worker (пакет `ts6`) | У TypeScript 7 нет JavaScript API |
| Тренажёр SQL | PGlite: настоящий Postgres прямо в браузере | Синтаксис как в работе, без расхождений SQLite |
| Тесты | Vitest (покрытие 100%), Playwright | Как в ваших проектах |
| Стили | Tailwind 4 | Как в ваших проектах |

Сначала платформа локальная и только для вас, запускается через `docker compose up`. Но в базе сразу есть таблица пользователей, и весь прогресс привязан к пользователю: открыть платформу другим можно будет, добавив вход, без миграции данных.

Сама платформа станет учебным полигоном для DevOps и SEO: её выкладка (Docker, nginx, CI, мониторинг, бэкапы) и SEO публичных страниц делаются по темам дерева.

## 8. Качество содержания

- **Источники:** у каждого листа есть ссылки на первичную документацию. Утверждения сверяются с ней, а не пишутся по памяти.
- **Проверки:** код в задачах проверяется автоматически: эталонное решение проходит тесты, заготовка — нет. Это делают `npm run content:check`, `npm test` и e2e.
- **Актуальность:** есть пометка версии («React 19», «Next.js 16») и дата проверки. Устаревшее видно.
- **Охват рынка:** на этапе 3 можно собрать требования из вакансий hh.ru и Habr Career и посмотреть, каких тем в дереве не хватает.
- **Честность:** у примеров из проектов есть пометка ✅ или 🔍. Спорные решения разбираются, а не выдаются за образец.
