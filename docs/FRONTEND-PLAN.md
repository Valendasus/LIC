# LIC · Frontend — подробный план специальности

> Первая специальность платформы. Структура блоков совпадает с разделом FE в [TOPIC-TREE.md](TOPIC-TREE.md); здесь — чем каждый блок наполняется: модули, примеры, практика, тренажёры, задачи.
> Каждая тема проходит три шага LIC: **Learn** (понять) → **Implement** (сделать) → **Confirm** (подтвердить и повторять).
> Составлено 08.11.2026. Версии и факты ниже проверены на эту дату; при наполнении каждой темы проверяются заново.

## 0. Что значит «по-настоящему компетентен»

Курс закончен, когда выполнено всё из двух списков. Это и есть критерий, а не число прочитанных тем.

**Готов к первой работе (Junior+):**
- **Вёрстка:** по макету из Figma — адаптивно, семантично, доступно с клавиатуры, без горизонтальной прокрутки на 320 px.
- **JavaScript:** без подсказок объясняю и пишу замыкания, `this`, прототипы, промисы и event loop. Реализую `debounce`, `Promise.all`, глубокое сравнение.
- **React:** приложение с формами, загрузкой данных, ошибками и состоянием в URL. Понимаю, почему компонент перерисовался.
- **Типы и код:** TypeScript без `any`, обобщённые компоненты, проверка ответа API через zod.
- **Next.js:** понимаю разницу серверных и клиентских компонентов, делаю страницы со SEO-метаданными.
- **Тесты:** пишу юнит-тесты и тесты компонентов, один e2e-сценарий.
- **Инструменты:** уверенно работаю в DevTools — Network, Performance, Application, отладчик.
- **Защита решений:** объясняю любое своё решение и называю компромисс.

**Готов к Middle:**
- **Архитектура:** проектирую фронтенд приложения: слои, FSD или своя схема, границы модулей, слой API, стратегия состояния. Пишу ADR.
- **Производительность:** нахожу и устраняю проблемы — Web Vitals, бандл, рендеры, длинные задачи, виртуализация.
- **Next.js глубоко:** Cache Components, `use cache`, ревалидация по тегам, стриминг, Server Actions с проверкой прав.
- **Устойчивость:** обновление токенов, гонки запросов, оптимистичные обновления, офлайн, realtime с переподключением.
- **Доступность:** делаю сложные компоненты (комбобокс, меню, диалог) по WAI-ARIA APG, проверяю скринридером.
- **Дизайн-система:** токены, headless-компоненты, Tailwind, Storybook, тесты.
- **System design:** провожу frontend system design за 45 минут по шаблону RADIO.
- **Чтение чужого кода:** разбираюсь в большом проекте (smallCRM, open-source) за день и нахожу в нём проблемы.

## 3. Задачи и тренажёры

### 3.1. Уровни задач

| Уровень | Что это | Подсказки |
|---|---|---|
| **Разминка** | 2–5 минут, один приём | Не нужны, сразу разбор |
| **Лёгкая** | 10–20 минут, одна тема | 1–2 подсказки |
| **Средняя** | 20–60 минут, сочетание тем, граничные случаи | Лестница из 3 подсказок |
| **Тяжёлая** | 1–3 часа, несколько тем, проектирование | Лестница из 4–5 подсказок, промежуточные проверки |
| **Босс** | Полдня и больше: своя мини-библиотека или фича целиком | Этапы с тестами на каждый, подсказки к каждому этапу, разбор архитектуры в конце |

### 3.2. Лестница подсказок

Чем тяжелее задача, тем ступенек больше, и каждая открывается отдельно:
1. **Направление:** что важно заметить в условии. «Обрати внимание: ответы могут прийти в другом порядке».
2. **Приём:** какой инструмент подходит. «Счётчик последнего запроса в замыкании».
3. **Каркас:** структура решения без логики.
4. **Ключевая строка:** самое неочевидное место.
5. **Решение с разбором:** почему так, сложность, альтернативы, как спросят на собесе.

Сколько подсказок открыто, учитывается в прогрессе. Задача, решённая с подсказкой 3+, возвращается в повторение раньше.

После решения:
- **вариация:** та же идея в другом обличье, чтобы проверить перенос;
- **«а если…»:** усложнение условия, например «а если нужна отмена?».

## 5. Блоки: наполнение, примеры, задачи

> Обозначения задач: Р — разминка, Л — лёгкая, С — средняя, Т — тяжёлая, Б — босс. 💡 — у задачи лестница подсказок (у всех С, Т и Б она есть всегда; значок ставится там, где подсказки особенно важны).
> Примеры: **[проект]** — из ваших проектов (PROJECTS-KB.md), **[OSS]** — из открытых проектов (раздел 6).

### FE1. HTML

**Модули:**
1. Документ и метаданные.
2. Семантика и структура.
3. Формы целиком: типы полей, `autocomplete`, `inputmode`, валидация.
4. Медиа и адаптивные изображения.
5. Таблицы.
6. Нативные интерактивные элементы: `dialog`, `popover`, `details`, `:open`.
7. Подсказки ресурсов.
8. SEO-разметка и JSON-LD.

**Примеры:**
- [проект] `robots.ts`, `sitemap.ts`, hreflang в лендинге; честный `lastModified` в avt-team.
- [OSS] разметка форм в React Aria и GOV.UK Design System (эталон доступных форм).

**Задачи:**
- **Р:** найти 10 ошибок семантики в фрагменте.
- **Л:**
  - форма регистрации, которую корректно заполняет менеджер паролей и автозаполнение браузера;
  - `picture` с AVIF и WebP и правильными `sizes`.
- **С:**
  - модальное окно на `dialog` без JS-библиотек: фокус, Esc, возврат фокуса 💡;
  - всплывающее меню на Popover API.
- **Т:** доступная таблица данных с сортировкой и подписями для скринридера 💡.
- **Проект:** P1.

### FE2. CSS

**Модули:**
1. Каскад, `@layer`, `@scope`, специфичность.
2. Блочная модель и потоки.
3. Flexbox.
4. Grid и subgrid.
5. Позиционирование, контексты наложения, `anchor positioning`.
6. Адаптивность: медиазапросы, container queries (размерные и style queries), `clamp`, `dvh`, `field-sizing`.
7. Современные селекторы: `:has`, `:is`, `:where`, `:open`, вложенность.
8. Цвет: OKLCH, `color-mix`, relative color syntax, `contrast-color()`.
9. Типографика и шрифты.
10. Анимации: transitions, `@starting-style`, scroll-driven animations, view transitions.
11. Архитектура CSS.
12. Кросс-браузерность и Baseline.
13. Производительность CSS.

**Примеры:**
- [проект] Тёмная тема и токены в ЭкоРеестре (MUI CSS-переменные).
- [проект] `globals.css` портфолио — одна дизайн-система в одном файле.
- [проект] Разбиение шрифтов по `unicode-range`.
- [OSS] Open Props, Every Layout, примеры CSS Wrapped 2025 от Chrome.

**Задачи:**
- **Р:** «какое правило победит» (T2-вариант для CSS), 30 карточек.
- **Л:**
  - центрирование 5 способами;
  - сетка карточек без медиазапросов (`auto-fit`, `minmax`);
  - липкая шапка таблицы.
- **С:**
  - холи-грейл макет на Grid с областями и перестройкой на мобильном (T6);
  - карточка, меняющая раскладку по ширине контейнера;
  - тултип на anchor positioning с переворотом у края экрана 💡;
  - индикатор прочтения на scroll-driven animations.
- **Т:**
  - «почини вёрстку»: страница с 8 багами — переполнение, `z-index`, сжатие flex-ребёнка, `100vh` на iOS, CLS от шрифта 💡;
  - тема на OKLCH с автоматическим контрастом и тёмным режимом.
- **Б:** P1 целиком, плюс сверка с макетом на 4 ширинах в T6.

### FE3. Подходы к стилизации

**Модули:** CSS Modules, BEM, CSS-in-JS и его цена в серверных компонентах, zero-runtime (vanilla-extract, Panda), выбор подхода.

**Примеры:**
- [проект] Emotion через MUI в ЭкоРеестре и НПЦ; Tailwind в smallCRM.
- [OSS] Mantine (переход с Emotion на CSS Modules — хороший разбор причин).

## 10. Как наполняем каждый блок (наш рабочий цикл)

1. **Исследование:** свежая документация и релизы, сверка версий, сбор реальных примеров (ваши проекты и открытые).
2. **Каркас:** модули → листья → цели.
3. **Learn:** объяснения в три слоя, демо, примеры, частые ошибки.
4. **Implement:** задачи всех уровней. У каждой — эталонное решение и тесты; проверка, что эталон проходит, а заготовка нет (это делает `npm run content:check`).
5. **Confirm:** вопросы на повторение и вопросы собеседования.
6. **Проверка:**
   - автоматические тесты всех задач;
   - запуск всех «что выведет»;
   - сверка фактов с первоисточником;
   - вы проходите блок и отмечаете, что непонятно.
7. **Пометки:** версия и дата проверки.
