# Вопросы с собеседований: что спрашивают и как это покрывает дерево

Собрано 11 ноября 2026. Данные: `docs/research/interview-questions.json`. Скрипты: `docs/research/scripts/`.

## Зачем

Вопросы с собеседований — внешний ориентир. Они показывают, какие темы считают обязательными, на каком уровне о них спрашивают и где у курса пробелы. Это не программа курса: сборники отстают от версий, в них много дублей и слабых формулировок. Курс строим по первоисточникам (`docs/research/sources/`), а вопросы используем как чек-лист: на каждый частый вопрос по теме урок должен давать ответ, а карточки и задачи должны его проверять.

## Как считали

1. **Классификация.** Каждому листу дерева сопоставлен набор ключевых слов на русском и английском (`scripts/rules.mjs`). Раздел или файл сборника подсказывает, какие ветки проверять первыми: вопрос из раздела про CSS сначала ищется среди тем CSS. Если ни одно слово не совпало, тема берётся по разделу. Точность проверена на случайных выборках: примерно 85–90% вопросов попадают в верную тему.
2. **Приоритет.** Самый большой сборник даёт три четверти всех вопросов, поэтому сырое число вопросов перекошено. Вместо него для каждого сборника считаем долю его вопросов по теме, а затем усредняем по всем сборникам. Это «доля внимания»: тема, которую заметно спрашивают во всех сборниках, стоит выше темы, раздутой одним сборником. Поле `rank` в данных — место по этой метрике.
3. **Уровни.** Уровни размечены только в части сборников: 373 вопроса junior, 330 middle, 132 senior. Этого хватает как подсказки, где тему копают глубже.

## Темы, о которых сборники молчат

Из 231 листа у 42 нет ни одного вопроса, ещё у 30 меньше пяти. Почти все они — новое в последних версиях или узкая практика:

- **Новые версии:** Tailwind 4 (6 из 7 тем), TypeScript 7, `useEffectEvent`, `Activity`, `ViewTransition`, React Compiler, Server Functions, Cache Components, `proxy.ts`, Navigation API, anchor positioning, scroll-driven animations.
- **Узкая практика:** сложные интерфейсы (таблицы, перетаскивание, редакторы, календари, медиа, импорт и экспорт), анимации (GSAP, three.js, шейдеры, Web Animations API), метод RADIO.
- **Перекрытия дерева:** «Сторы: Zustand и Redux Toolkit» в блоке «Состояние» и «Zustand и Redux Toolkit» в экосистеме React — вопросы ушли во второе. Так же «Контролируемые и неуправляемые» в паттернах пересекается с «Управляемыми и неуправляемыми полями» в основах. Стоит развести их по смыслу: в основах — механика, в паттернах — проектирование API компонента.

**Вывод.** По этим темам сборники не помогут, они отстают от версий на год-два. Здесь материал полностью строим по первоисточникам: документации, спецификациям, заметкам к релизам. Зато на собеседовании знание новых возможностей выделяет кандидата.

## Как вопросы превращаются в карточки и задачи

Правило для каждой темы, когда пишем или переписываем урок:

1. Открыть вопросы листа в `interview-questions.json`, отсортировать по частоте и уровню.
2. Отметить вопросы, на которые урок не отвечает, и дописать урок по первоисточникам, а не по ответам из сборников.
3. Частые вопросы, которые проверяют понимание, а не определение, превращаются в карточки. Вопрос «что такое X» превращается в карточку, только если без X не понять тему.
4. Вопросы вида «что выведет код», «реализуйте», «почему тут баг» превращаются в задачи: на вывод, на порядок, с редактором.
5. Вопросы senior-уровня — материал для задач уровня «сложно» и «босс» и для раздела о реальной работе.

## Ограничения

- Классификация — по ключевым словам. Примерно каждый десятый вопрос лежит не в той теме. Для приоритета это допустимо, но перед карточкой вопрос перечитываем.
- Дубли убраны только точные. Близкие формулировки на разных языках остаются отдельными вопросами.
- Сборники — не первоисточник. Формулировки бывают устаревшими (`componentWillMount`, `getInitialProps`) или неточными. В курс идёт актуальное знание, а устаревшее — только как «так было раньше и вот почему изменилось».
