# Области видимости, hoisting и TDZ

Лист: `javascript/scope/scope-hoisting`. Приоритет: 5 (63 вопроса, 5 сборников из 6).

## Что обязательно знать

- **Область видимости лексическая**: определяется местом в коде, а не местом вызова. В спецификации она выражена через Environment Record. У каждого есть ссылка на внешний (`[[OuterEnv]]`), из них складывается цепочка, по которой ищется имя (§9.1).
- **Виды областей:** глобальная, модульная (у каждого ES-модуля своя), функциональная, блочная (`{}`, `for`, `if`, `switch`, `catch`, `class`).
- **`var`** — область функции (или глобальная), объявление поднимается и сразу инициализируется `undefined`. Повторное объявление разрешено. На верхнем уровне классического скрипта становится свойством `globalThis`.
- **`let` / `const`** — блочная область. Привязка создаётся при входе в блок, но не инициализируется до строки объявления. Промежуток между началом блока и объявлением — **временная мёртвая зона (TDZ)**: любое обращение даёт ReferenceError. На верхнем уровне скрипта `let`/`const` не становятся свойствами `globalThis`, но видны во всех скриптах страницы.
- **`const`** запрещает переприсвоить привязку, но не делает значение неизменяемым: `const a = []; a.push(1)` работает.
- **Function declaration** поднимается целиком, вместе с телом: функцию можно вызвать до объявления. **Function expression** и стрелка подчиняются правилам своей переменной (`var` → `undefined`, `let`/`const` → TDZ).
- **`class`** поднимается как `let`: до объявления TDZ.
- **Hoisting — не перенос кода.** Это следствие двухфазной обработки: сначала создаются привязки всей области (`FunctionDeclarationInstantiation`, `GlobalDeclarationInstantiation`), потом выполняется код.

## Тонкие места

- `typeof x` в TDZ — ReferenceError, хотя для необъявленного `x` это `'undefined'`.
- TDZ зависит от времени, а не от места в коде: функция, объявленная выше `let x`, может читать `x`, если её вызвали после инициализации.
- `let x = x + 1` → ReferenceError: правая часть вычисляется в TDZ.
- Параметры по умолчанию — отдельная область: `function f(a = b, b = 1) {}` → ReferenceError при вызове `f()`.
- Цикл `for (let i …)` создаёт новую привязку `i` на каждую итерацию. Поэтому замыкания в цикле видят разные значения. С `var` все видят одну переменную. Связь с темой closures.
- Объявление функции внутри блока в нестрогом режиме ведёт себя по правилам Annex B (веб-совместимость): функция видна снаружи блока как `var`. В модулях и строгом режиме — только внутри блока.
- **Строгий режим** (`'use strict'`) запрещает неявные глобальные переменные, `with`, дубли параметров, делает `this` в простом вызове `undefined`. Модули и тела классов всегда строгие.
- **Глобальная область.** Свойства `window` (например, `name`, `status`) уже существуют, `var name = 1` превратит число в строку `'1'`. Отсюда совет не трогать глобальную область, а писать модули.
- `globalThis` (ES2020) — единое имя глобального объекта для браузера, воркеров и Node.

## Что изменилось

- Сама механика не менялась с ES2015.
- ES2025: «redeclarable global eval-introduced vars» — узкая правка для `eval`, на практике не важна.
- Новое объявление `using` / `await using` (ES2027) подчиняется тем же правилам, что `const`: блочная область и TDZ. В конце блока вызывается `[Symbol.dispose]()`. См. errors.md.

## Идеи для практики

- **Задачи на вывод** (5–6 штук): `console.log` до `var`, до `let`, вызов function declaration до объявления, `typeof` в TDZ, затенение переменной в блоке, параметр по умолчанию, ссылающийся на следующий.
- **Карточки:** что поднимается и с каким значением (таблица var / let / const / function / class); почему `const` не делает объект неизменяемым.
- **Задача на поиск ошибки:** код, где `var` в цикле ломает обработчики. Исправить двумя способами.
- **Визуализация (демо):** окружения и цепочка поиска имени, общая с замыканиями.
