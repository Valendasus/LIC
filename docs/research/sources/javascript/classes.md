# Классы, наследование, приватные поля

Лист: `javascript/objects/classes`. Приоритет: 7 (58 вопросов, 5 сборников из 6). Тесно связан с prototypes.md.

## Что обязательно знать

- **Класс — синтаксис над прототипами**, но не только сахар. Отличия от функции-конструктора:
  - вызов без `new` → TypeError;
  - тело всегда в строгом режиме;
  - методы неперечисляемые и без `prototype`, их нельзя вызвать с `new`;
  - объявление поднимается с TDZ, как `let`;
  - `extends` работает и со встроенными типами (`class MyArray extends Array`) — функции-конструкторы так не умеют;
  - есть приватные элементы, статические блоки и `super`.
- **Что из чего состоит:**

| Элемент | Где живёт |
|---|---|
| `constructor` | сама функция класса |
| методы, геттеры, сеттеры | `Class.prototype` |
| поля `x = 1` | на каждом экземпляре, создаются через `[[DefineOwnProperty]]`, а не присваивание |
| `static` | на самом классе |
| `#private` | во внутреннем хранилище экземпляра, недоступны снаружи |
| `static { }` | выполняется один раз при определении класса |

- **Порядок создания экземпляра:** в базовом классе сначала инициализируются поля, потом выполняется тело конструктора. В наследнике `this` недоступен до `super()`: обращение раньше даёт ReferenceError. Поля наследника инициализируются сразу после возврата из `super()`.
- **Приватные элементы** `#x` (ES2022): проверка «есть ли у объекта поле» — `#x in obj`. Доступ к `#x` у чужого объекта → TypeError. Приватность жёсткая: нет ни рефлексии, ни Proxy-прохода. Наследник не видит `#x` родителя.
- **Геттеры и сеттеры** — свойства-аксессоры, задаются в прототипе.
- **`super.method()`** ищет метод в прототипе родителя через `[[HomeObject]]` метода, поэтому скопированный в другой объект метод продолжит ссылаться на старого родителя.

## Тонкие места

- **Поля и сеттеры родителя.** Поле наследника `x = 1` *определяет* свойство и не вызывает сеттер `x` родителя. TypeScript со старым `useDefineForClassFields: false` вёл себя иначе (присваивал), это источник багов при миграции.
- **Метод, вызванный в конструкторе родителя**, видит ещё не инициализированные поля наследника.
- **Наследование от встроенных типов.** `class MyErr extends Error` работает; методы вроде `map` у наследника Array возвращают экземпляр наследника (`Symbol.species`).
- **Миксины** `const Timestamped = (Base) => class extends Base {}` — способ составлять поведение без глубокой иерархии.
- **Абстрактный класс** в JS: проверка `new.target === Abstract` в конструкторе → ошибка. В TypeScript — `abstract`.
- **Декораторы.** Предложение TC39 в 2022 году дошло до стадии 3, а потом вернулось на стадию 2.7 для доработки (так в списке предложений на ноябрь 2026). В стандарт не вошло, нативно в браузерах не поддерживается. TypeScript 5+ и Babel поддерживают вариант по предложению; старые `experimentalDecorators` (на них построены Angular и NestJS) с ним несовместимы. На собеседованиях спрашивают — нужно уметь объяснить разницу.
- **Композиция или наследование.** Во фронтенде почти всегда выигрывает композиция: глубокие иерархии классов хрупкие. Классы уместны для сервисов, ошибок, структур данных, Web Components.

## Что изменилось

- ES2022: публичные и приватные поля, приватные методы, `static`-блоки, `#x in obj`.
- С тех пор синтаксис классов не менялся. Декораторы — на стадии 2.7.
- Из TypeScript: `useDefineForClassFields` по умолчанию `true` при `target` ≥ ES2022.

## Идеи для практики

- **Задачи на вывод:** порядок логов при создании наследника с полями и вызовом метода из конструктора родителя; `this` до `super()`.
- **Задача с редактором:** `myNew(F, ...args)`; класс `EventEmitter` с приватным хранилищем; `class TypedError extends Error` с `cause` и правильным `name`.
- **Карточки:** где живут поля, методы, static; что даёт `#x in obj`; почему поле наследника не вызывает сеттер родителя.
- **Задача из работы:** переписать иерархию из трёх классов на композицию.
