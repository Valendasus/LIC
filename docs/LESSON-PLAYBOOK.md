# Как делаем уроки

Рабочий план производства уроков. Цель — каждый урок по одному маршруту, без перечитывания старых уроков и самодельных скриптов, с качеством из `CLAUDE.md` («Главное: качество учебного материала»).

Документ состоит из трёх частей:
1. маршрут одного урока — что делаем и в каком порядке;
2. нормы — из чего состоит готовая тема;
3. инструменты, которые делают маршрут дешёвым, — что уже есть и что строим.

---

## 1. Маршрут одного урока

| Шаг | Что делаем | Результат | Чем проверяем |
|---|---|---|---|
| 0. Выбор | Берём следующую тему из порядка в `docs/PLAN.md` | id листа, например `javascript/async/async-await` | — |
| 1. Исследование | Открываем заметку `docs/research/sources/<блок>/<лист>.md`. Если её нет — сначала пишем её по шаблону заметок (`docs/research/sources/javascript/README.md`) | Заметка: что знать, тонкие места, что изменилось, вопросы, идеи практики, источники | Утверждения о поведении кода — запуском, поддержка — по web-features и MDN BCD |
| 2. Каркас | `npm run new:topic <id>` | Три файла с заготовками и метками `TODO`, тема в дереве отмечена наполненной | `content:check` падает, пока есть `TODO` |
| 3. Цели | 4–6 целей в `tree.yaml`: глаголы «объяснить», «предсказать», «написать», «найти и исправить» | Цели, по которым видно, что ученик умеет после темы | Каждой цели соответствует хотя бы одно задание |
| 4. Learn | Текст по скелету из части 2 | `.mdx` | Каждый пример «что выведет» — запуск через `npm run content:run` |
| 5. Практика | Карточки и задания по нормам из части 2 | `.cards.yaml`, `.practice.yaml` | `content:check -- <id>`: ответы запускаются, эталоны проходят тесты, заготовки — нет, нормы соблюдены |
| 6. Implement и Confirm | В уроке — ссылки на задания `<Practice id="…" />` и 5–7 вопросов `<Question>` | Урок без дублирования заданий | — |
| 7. Сверка с собеседованиями | Частые вопросы темы из `interview-questions.json` (их вставляет каркас) — на каждый есть ответ в Learn и проверка в карточке или задании | Отмеченный список в заметке исследования | Ручной просмотр по списку |
| 8. Проверка | Тема: `content:check -- <id>`, `vitest`, e2e проверки эталонов. Полный e2e — в конце блока тем | Всё зелёное | Команды из части 3 |
| 9. Готово | Чек-лист из части 2 → запись в `CHANGELOG.md` (5–8 строк) → коммит | Коммит «Урок «…»» | — |

**Как экономим:** на каждом шаге читаем только этот документ, заметку исследования и свои три файла. Старые уроки и `scripts/content-check.mjs` не перечитываем: формат — в части 2, ошибки формата покажет проверка.

## 2. Нормы

### Скелет Learn

1. **Суть за минуту** — 2–4 предложения и один короткий пример. После него ученик понимает, зачем тема.
2. **Как устроено** — 3–6 разделов `###`, по одной идее на раздел. Порядок: от механизма к применению. Каждое новое понятие вводится до использования, у каждого утверждения — код.
3. **Новое в последних версиях** — если в заметке исследования есть изменения. Статус поддержки словами («во всех браузерах», «нет в Safari»), без кодов Baseline в тексте.
4. **Из реального кода** — 1–2 `<Example>`: одно `good`, одно `review`. Путь к файлу — условный, без названия проекта.
5. **Под капотом** — `<Callout type="deep">` для спецификации и граничных случаев, которые не нужны с первого раза.
6. **Частые ошибки** — таблица «ошибка → признак → исправление».
7. **На собеседовании** — `<Callout type="interview">`: как отвечать сильно, что любят спрашивать.

Объём — по сложности темы, а не по шаблону. Простой раздел — абзац, сложный — с таблицей и двумя примерами.

### Состав практики

| | J | M | S |
|---|---|---|---|
| Карточки | 12–16 | 10–14 | 8–12 |
| Быстрые задания: «что выведет», квиз, порядок | 10–14 | 8–12 | 6–10 |
| Задачи с кодом | 4–6 | 4–6 | 3–5 |
| Уровни задач | от разминки до сложной | от лёгкой до сложной, желательно босс | средняя, сложная, босс |

- **Карточки:** термины (`term`, ключевые — с `reverse: true`), вопросы на понимание (`qa`), код (`code`, «что не так»).
- **Быстрые задания:** «что выведет» — на механизм, а не на память; квиз — с объяснением каждого неверного варианта (`why`); порядок — для процессов и последовательностей.
- **Задачи с кодом разного типа**, не вариации одной:
  - **написать** — реализовать функцию;
  - **починить** — заготовка с ошибкой;
  - **предсказать** — вынести в «что выведет»;
  - **переписать** — старый код на современный;
  - **спроектировать** — задача в Implement с разбором словами.
- **Подсказки** — лестница: направление → приём → каркас → ключевая строка. Для средних не меньше 2, для сложных и босса — не меньше 3.
- **Разбор** (`explain`): почему так, альтернативы, «а если…», что спросят на собеседовании.
- **Заготовка не должна зависать.** Проверка запускает заготовки в Node без таймера воркера: никаких `[...источник]` на бесконечных генераторах и `while (true)` без выхода — заготовка должна просто проваливать тесты.
- **Строки YAML с «: » или « #»** берутся в кавычки, иначе файл не разберётся.
- **Задачи не повторяются между темами.** Перед написанием смотрим список ключей соседних тем: каркас вставит его комментарием.

### Темы, которые не проверить в Node

Воркеры, iframe, общение окон, наблюдатели, Service Worker: логику выносим в чистую функцию и тестируем на фейках из помощников (часть 3) — фейковый воркер, пара окон, фейковые `cache` и `fetch`, моки наблюдателей. Реальное поведение — React-задача в песочнице `/sandbox` или демо.

### Чек-лист «тема готова»

- [ ] Семь критериев качества из `CLAUDE.md` выполнены.
- [ ] Цели темы покрыты заданиями.
- [ ] Частые вопросы с собеседований отмечены в заметке исследования и покрыты.
- [ ] Нормы состава выполнены (проверка `content:check`).
- [ ] `meta.verified` — сегодняшняя дата, `meta.versions` — версии из заметки.
- [ ] Нет названий проектов владельца, внутренних кодов и оценок времени.
- [ ] Проверки зелёные, запись в журнале, коммит.

## 3. Инструменты

### Уже есть

- UI-кит `shared/ui` и блоки урока `Callout`, `Example`, `Task`, `Hints`, `Question`, `Sources`. Новый урок не требует кода интерфейса.
- Тренажёры всех видов заданий, расписание повторений, проверка `content:check` (запуск ответов, эталонов и заготовок).
- Исследования: `docs/research/interview-questions.json`, заметки `docs/research/sources/`.

### Сделано 11.11.2026

| # | Инструмент | Что даёт | Как устроено |
|---|---|---|---|
| И1 | `npm run new:topic <id>` | Три файла-заготовки с метками `TODO`. В заготовке практики комментарием — частые вопросы темы из исследования и ключи заданий соседних тем. В `Sources` — ссылки из заметки. Тема отмечена `content: true` | Скрипт с тестами; на существующей теме — понятная ошибка |
| И2 | `content:check -- <id>` и `npm run content:run` | Проверка одной темы за секунды. Запуск фрагмента кода в той же песочнице, что и проверка ответов | Фильтр по id или префиксу (`javascript/async`), `content:run` читает файл или stdin |
| И3 | Нормы и `TODO` в `content:check` | Тема с `TODO` или ниже норм состава не проходит проверку. Нормы — таблица из части 2 по `grade` | Сообщения вида «javascript/async/x: задач с кодом 2, нужно не меньше 4 (M)» |
| И4 | `<Practice id="…" />` в MDX | Задание из `practice.yaml` прямо в уроке: «что выведет» с ответом под подсказкой, квиз, порядок, задача — карточкой-ссылкой в редактор. Один источник вместо копии в тексте | Компонент в `entities/lesson`, тест рендера; урок «Event loop» переведён на него |
| И5 | Помощники в тестах задач | `deferred()`, `flaky(n)`, `trackConcurrency()`, `fakeWorker()`, `fakeWindows()`, `fakeObserver()` — доступны в тестах, как сейчас `spy` и `sleep` | В `code-runner`, с тестами; описаны в `docs/TRAINERS.md` |
| И6 | Автоматический список тем в e2e | Проверка «все эталоны решаются в браузере» берёт все наполненные темы сама, без ручного списка | e2e находит темы по дереву |

Готовые уроки переведены на новую схему: «Event loop», «Замыкания», «Промисы» и «Каскад, специфичность» соблюдают нормы, копии заданий в тексте заменены на `<Practice>`.

## 4. Очередь уроков

Порядок из `docs/PLAN.md` (приоритеты от 11.11.2026):

1. **Асинхронность JS:** async/await → комбинаторы → отмена и гонки → генераторы и асинхронные итераторы → доработка event loop.
2. **Браузер изнутри:** процессы и потоки → кадр → Web Workers → общая память → общение окон → iframe → Service Worker → наблюдатели.
3. **Остальной JavaScript** по приоритету исследования вопросов: приведение типов → области видимости → классы → итерация → `this` → массивы → функциональные приёмы → неизменяемость → модули → ошибки → и далее.

Полный e2e и сверка журнала — в конце каждого из трёх блоков.
